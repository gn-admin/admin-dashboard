# GN-Encuestas / Admin Dashboard — Contexto del proyecto

> Lee también `PROGRESO.md` (estado actual y pendientes detallados) y `README.md` (puesta en marcha).

## Qué es
PWA admin de Grupo Nebak: encuestas de Google Forms (pre-adopción perros/gatos + solicitud de acogida), gestión de animales, familias acogedoras, adopciones, socios, lista negra y reportes. Backend en Google Apps Script (hojas de cálculo), auth con Firebase (email/contraseña).

## Comandos
- `npm run dev` — genera config (`.env` → `src/js/config.js` y `apps-script/Config.gs`) y sirve en `http://localhost:8080`.
- `npm run build` — regenera la config manualmente (`node scripts/gen-config.js`).
- `node scripts/gen-config.js` — script de generación: no editar `src/js/config.js` ni `apps-script/Config.gs` a mano, se regeneran.
- `npm test` (`node --test tests/*.test.js`) — unitarios de lógica pura del front, sin dependencias (**344 tests**). Seis ficheros: `dashboard.test.js` (reglas de negocio + helpers del home v22 + multiusuario), `cobertura.test.js` (escapeo, fechas, widgets, fichas, memoria, capacidades, blacklist, estados, fluidez), `api.test.js` (contrato HTTP: `text/plain`, **sin cabecera `Authorization`**, clave compuesta, reintento, `status`), `diseno.test.js` (contraste WCAG AA leído del CSS + integridad de clases/ids/iconos + manifest/PWA), `pdf-export.test.js` (builders de PDF) y `auth.test.js` (mensaje de login anónimo y aislamiento de caché por cuenta). Los tests que mutan estado usan `beforeEach` (el `Dashboard` es un single y si no se pisan entre ficheros). **Corren en CI** (`.github/workflows/deploy.yml` ejecuta `npm test` tras generar la config: un test en rojo bloquea el despliegue). El workflow usa Node 20 y los tests no necesitan `src/js/config.js` (no se lee de los tests).

## Reglas importantes
- **Nunca subir datos sensibles**: `.env` (valores reales), `src/js/config.js` y `apps-script/Config.gs` (generados) están en `.gitignore`. Para GitHub Pages, las variables se añaden como Repository secrets y el workflow `.github/workflows/deploy.yml` las inyecta (`secrets.X || vars.X`). **El repo es PÚBLICO**: usar siempre Secrets (encriptados), nunca Variables planas.
- **Estados y notas usan clave compuesta `survey_id::id`** (los ids `resp_N` colisionan entre encuestas). `handleSetEstado`/`handleSetNota` deben hacer match por `response_id` Y `survey_id`.
- **CORS POST**: Apps Script no responde preflights con `application/json`. Enviar siempre `Content-Type: text/plain;charset=utf-8` (véase `src/js/api.js`); el backend hace `JSON.parse(e.postData.contents)`.
- **Apps Script responde HTTP 200 con campo `status`** (`success` | `warning` | `error`) y, si falla, `error` (mensaje). `api.js` lanza por `status`/`data.error` con `err.status`; el front pinta el snackbar con `Dashboard._snackErr(err, msg)` (gris neutro si `warning`, rojo si `error`). **Todo `catch` que muestre snack debe usar `_snackErr`, nunca `showSnackbar(msg,'error')` a fuego** (si no, un `warning` del backend se pinta en rojo); `_snackErr` delega en `_snackTipo(err)` (pura, testeada): rojo **solo** con `status: 'error'` explícito o `HTTP NNN` en el mensaje; 429 y «sin configurar»/«no configurado» son aviso; cualquier fallo sin clasificar (red caída, `Failed to fetch`, status desconocido) también es **gris neutro**. `showSnackbar(msg)` sin tipo usa `neutral` por defecto, nunca rojo. Colores: verde `--primary`, **gris neutro `--gray-200` con texto `--gray-800`** en avisos, rojo `--danger`, más barra lateral de 5px por tipo.
- **Urgencias de animal**: campo booleano `urgente` (checkbox *Necesita acogida/adopción urgente*). Se lee con `_esUrgente(a)` (acepta `true`/`1`/`'TRUE'`/`'SI'`, como devuelve Sheets), pero **lo que se pinta y se ordena es `_esPrioritario(a)`** = urgente **y** estado `disponible`/`en_acogida` (un adoptado/fallecido/reservado con el check no lleva badge ni se adelanta). El orden lo hace `_ordenaUrgentes(lista)` —no muta— en el selector de asignación y en *Vincular animal*. La insignia `.urgente-badge` va dentro de `.animal-card-pills` (flex + wrap, evita que pelee con el badge de estado). **La columna `urgente` la auto-añade el backend** (`appendToSheet`/`updateSheetRow` añaden columnas que falten): si el `Code.gs` desplegado es anterior, el campo no se guarda.
- **Selects sueltos**: los que van dentro de `.detail-field` (asignación de animal/familia) usan la clase **`.form-input`** (existe en CSS: borde, foco, flecha `appearance:none`, margen 12px y 44px táctiles). `.form-control` **no existe** en este proyecto.
- **Contraste WCAG AA**: snackbar éxito/error y `.urgente-badge` usan `--primary-hover` / `--danger-hover` (blanco sobre `--primary` da 2,2:1 y sobre `--danger` 3,8:1; ambos fuera de AA). El aviso `warning` y el `neutral` usan gris `--gray-200` con texto `--gray-800` (contraste AA). **Todos los pares de botones ya cumplen**: `.btn-primary` usa `--primary-hover` (#15863D, 4,7:1) con hover `#0f6b31` (6,6:1); `.btn-danger` fondo `--danger-hover` (5,4:1) con hover `#a93226` (6,6:1); `.btn-outline-green` texto y borde `--primary-hover` (4,7:1) con hover `--primary-dark` sobre `--primary-lighter` (10,6:1). **Están los 4 pares de botones + toasts/badge en `tests/diseno.test.js`**, que lee el CSS: si alguien cambia una variable, el test avisa. Checkboxes: regla `.form-group input[type=checkbox]` que elimina el padding/borde/min-height que heredan del input de texto (la diana de 44px la aporta `label:has(input[type=checkbox])`). `font-size:16px` también en `@media (pointer: coarse)` para que Safari no haga zoom al enfocar en iPad.
- **Service worker**: al tocar `src/js/dashboard.js`, `app.js`, `api.js`, `auth.js`, `pwa.js` u otros, subir `CACHE_NAME` en `src/sw.js`. Estado actual: `gn-encuestas-v140`.
- **Flujo de adopción (fases, contrato, entrega y prueba)**: las fases siguen siendo las históricas (`Encuesta recibida → Revision → Visita domiciliaria → Contrato → Entrega → Prueba → Seguimiento`) para no romper los datos de las hojas. Reglas puras y testeadas: `_faseInfo(fase)` (descripción y tono), `_requisitoAvance(p, contrato, seguimientos)` —bloquea desde `Contrato` sin firma, desde `Entrega` sin `fecha_entrega` o con el checklist obligatorio incompleto (`_entregaFaltantes`; los ítems `opcional` no bloquean) y desde `Prueba` sin `_pruebaRegistrada`— y `_faseGuia(p, contrato)` (tarjeta de siguiente paso con CTA). `retrocederFase` **pide confirmación** con `_confirm(msg, title, okLabel)` antes de revertir, avisando de los datos que se conservan. El modal de contrato es **a pantalla completa** (`modal-overlay--full` + `modal-box--full`, documento y formulario en dos paneles; en móvil/tablet el documento ocupa toda la pantalla y se vuelve con *Volver a la firma* → `_toggleContratoDoc`), exige aceptar términos (`ct-acepta`) y usa `_contratoTerminosHtml(p, contrato)` como documento base. `showContratoDoc` abre el documento firmado/pendiente en el mismo visor. La entrega guarda `fecha_entrega`, `entrega_checklist` (JSON; `contrato` se fuerza), `entrega_observaciones`, `entrega_recibe` y `entrega_foto_url`/`entrega_foto_id` (foto opcional a Drive vía `uploadDocumento`). La **prueba** se guarda como fila de `seguimientos` con `tipo: 'Prueba'`, `resultado` y `checklist` (JSON): es el periodo corto de adaptación (15-30 días), distinto del **seguimiento** a largo plazo, que se muestra en **todas** las fases con `_seguimientosFicha` y una línea temporal de hitos (`_seguimientoHitos` calcula 1, 3, 6 y 12 meses desde `fecha_entrega`; se marcan con `hito: '1m'|'3m'|'6m'|'12m'`). Envío por email: `API.sendContratoEmail` → `send-contrato-email` (el backend solo acepta emails del contrato + `CONTACT_EMAIL` + usuario autenticado; el modal marca adoptante, tutor y copia a Grupo Nebak); si el endpoint no existe (`_debeOfrecerMailto`) se cae a `mailto:` con `_mailtoHref`.
- **Identidad del animal en contratos (v134)**: `_contratoAnimalEditorHtml` (foto + nombre, compartido por adopción y acogida) y `_aplicarIdentidadAnimalContrato` (sube a Drive con `uploadFotoAnimal`, actualiza la ficha y el caso). La foto es **obligatoria** si el animal no tiene; sin foto no se firma. El nombre puede corregirse o cambiarse en el contrato y se sincroniza con `animales.nombre`, `adopciones.animal` y `acogidas.animal`. Los contratos ya firmados ofrecen *Foto / nombre* (`showContratoIdentidad`) sin anular la firma. La ficha de adopción usa `_faseStepperHtml`/`_faseProgreso`; la cabecera del detalle muestra foto, fase y progreso; las listas usan `_adopcionCardHtml`/`_acogidaCardHtml`. El contrato de acogida no se guarda ni descarga sin foto; los contratos de adopción antiguos sin foto se completan desde la ficha antes de descargar o enviar.
- **Fluidez (plan A-F)**: **Ningún `transition: all`** en `styles.css` (10 pasaron a propiedades explícitas: `transform`, `box-shadow`, `background`, `border`, `opacity`…). `:active` de tarjetas (`.response-card`, `.animal-card`, `.bl-card`) con `scale(0.99)`. `.loading-overlay` es **siempre `display:flex`** y se muestra/oculta por `opacity`+`visibility`+`pointer-events` (fade 0.15s; la regla print con `display:none !important` sigue mandando) y **sin `backdrop-filter` en `pointer: coarse`**. Modales: **`Dashboard._modalScrollLock(open)`** con ref-count (`_modalLocks`) al abrir/cerrar `showInfoModal`/`showFormModal`/`_confirm` (y sus cierres); nunca tocar `body.style.overflow` a fuego. Navegación y detalle se ejecutan **directamente** (`_withViewTransition(fn)` es hoy un simple `fn()`); **NO usar `document.startViewTransition`**: probado y retirado — con la API presente pero inestable el callback no llegaba a ejecutarse y las pantallas/fichas salían en blanco. Entrada de listados: **`_animaListado(container)`** añade la clase `.list-fresh` (keyframes `cardFade`, quita la clase a los 250ms); se llama **solo al final de `renderEncuesta`/`renderAnimales`/`renderFamilias`/`renderAdopciones`/`renderAcogidasActivas`/`renderBlacklist`, nunca en `filterXxx`** (evita parpadeo al teclear).
- **Carga percibida (v125)**: cache-first. `_hydrateCache` marca `_cached` y `init` ya no espera al perfil ni a surveys/estados/notas para ocultar el overlay; el perfil se pinta en segundo plano. `_loadSurveys`/`_loadResponses`/`_loadList`/`loadEstados`/`loadNotas` devuelven la copia local si existe y revalidan detrás; sin caché esperan red. `loadPage` pinta `.page-skeleton` y `viewCuestionarioModal` abre el modal con `_modalSkeleton` (sin overlay global). `_refreshHome` fuerza red para repintar el home cuando llega.
- **Contrato de adopción (v132)**: documento formal con `REUNIDOS`, `EXPONEN` y `CLÁUSULAS`; **no se muestra el rol del adoptante** ni en el formulario ni en el PDF. Si se marca **tiene tutor**, se muestra una sección propia, se exige su nombre y firma y el PDF añade una **página de anexo** (`break-before: page`) con sus datos; adoptante y tutor firman ambos. El documento incluye **datos de la asociación** (nombre, CIF, domicilio, registro, email, teléfono y web; se leen de `ASOCIACION_*` y caen a `CONTACTO_*`) y un **sello generado con el logo** en la cabecera y en la firma de la entidad. Los contratos nuevos guardan `entidad_*` y `terminos_*` como copia; los antiguos se completan desde la config. El PDF y el modal comparten cláusulas; `_terminosAdopcionClausulas`/`_terminosAdopcionHtml` y `PdfExport._buildTerminosAdopcion` generan el **anexo “He leído términos y condiciones”**, enlazado desde `ct-acepta`. Al firmar, `ct-enviar` (marcado por defecto) intenta enviar **contrato + términos** por email; el correo del backend incluye ambos documentos completos en HTML, no PDFs adjuntos (el PDF se imprime desde el navegador). `_contratoTutor` distingue tutor de entidad; `_printAsync` espera logo/foto antes de imprimir.
- **Contrato de acogida (v130, opcional)**: en cada caso de *Acogidas activas* hay un botón **Contrato de acogida** que abre una previsualización y permite descargar un PDF con los datos del animal, la familia y la solicitud. Se puede **guardar una copia de los datos** (no el PDF) en la hoja `Contratos` con `tipo: 'acogida'`, `acogida_id` y el snapshot completo en `datos_json`; al reabrir el caso se regenera desde esa copia, aunque cambien las fichas. `Actualizar copia` reemplaza el snapshot. Es opcional y **no bloquea `avanzarFaseAcogida`**. `Dashboard._contratoAcogidaDatos`, `_contratoAcogidaDe`, `_contratoAcogidaSnapshot`, `_contratoAcogidaFila` y `PdfExport._buildContratoAcogida` cubren el flujo; al descargar sin copia previa se guarda automáticamente. La hoja `Contratos` es compartida: `_contratosAdopcion` excluye las filas de acogida de los KPIs de adopción. No hace falta endpoint ni hoja nuevos; el `Code.gs` desplegado debe incluir el auto-alta de columnas de `appendToSheet`/`updateSheetRow`.
- **Foto de la ficha de animal**: el avatar del héroe es un `<button class="foto-hero">` que abre la imagen en modal (`verFotoAnimal` → `showInfoModal` con `img.modal-foto`, src `w1600` con reintento a `w800`). El HTML lo construye `_fotoHero(a)` (pura, testeada): con foto → botón; sin foto → icono de especie.
- **Ficha de socio y edición inline**: `viewSocio` usa **héroe compacto** (avatar 72px con `flex-shrink:0` + nombre + badges + email/teléfono) y todos los campos a **ancho completo debajo**; la foto **no** va en columna al lado de la ficha (así la imagen no empuja/desplaza los datos, como ya pasaba en Animales). Al pulsar *Editar*, `Dashboard._renderForm(pageId, html)` **sustituye la ficha por el solo formulario** (guarda la anterior en `detailEl._prevHTML`) y `cancelForm` la **restaura**; antes el formulario convivía con la ficha vieja por debajo. Reglas puras y testeables: `_renderFormMode(listHidden, detailActive)` y `_formCancelAction({active,hasPrev,hasForm,listHidden})` → `from-list|from-detail|none` y `restore|clear-detail|remove-form|clear-container`. Igual para Familias y Adopciones (usan el mismo `_renderForm`).
- **Login sin filtrar el proveedor**: `Auth._msgLogin(err)` (pura, testeada) traduce cualquier error de autenticación a una frase genérica en castellano sin `auth/…`, sin «Firebase» ni copia de `err.message`; `loginWithEmail` relanza solo ese mensaje y `app.js` pinta **siempre** `Auth._msgLogin(err)`, nunca `err.message`. El mismo criterio en `console.error` y en el rechazo de `_loadFirebaseSDK` («No se pudo cargar el módulo de acceso»). **Nota**: el bundle sigue mostrando `CONFIG.firebase.authDomain` y los `<script>` de `gstatic.com` (inherente a auth en cliente); esto solo evita exponerlo en los mensajes de error.
- **Filtro de urgentes**: `Dashboard._currentPrioridadFilter` (`'all'|'solo'`) en el third `<select>` de *Animales*, combinable con estado y especie; aplica `_esPrioritario`. Además `renderAnimales` **ordena con `_ordenaUrgentes`** (no muta) para que los urgentes encabecen cada bloque.
- **Anti doble-tap de fase**: `avanzarFase` / `retrocederFase` / `avanzarFaseAcogida` pasan por `_busyStart(k)` + `finally _busyEnd(k)` (Set `Dashboard._busyOps`); la llave se libera aunque se cancele el `_confirm`.
- **Registro de actividad (pantalla `#actividad`)**: sidebar *Herramientas* + *Más* + `page-actividad`; `renderActividad`/`filterActividad`/`exportActividadCsv` sobre `this.actividad` (best-effort con `API.getActividad`). `_regLog` además `_cacheSet('actividad', …)` para que no se pierda entre recargas. `actividad` **no** está en `saveLocal()`; se persiste por `_cacheSet`.
- **Horas de voluntariado**: en la ficha del socio (solo `Voluntario`/`Ambos`) hay *Registrar horas* → `registrarHoras` suma sobre `horas_mes` y sella `ultima_actividad` (columnas ya existentes, **sin columnas nuevas**), con `reiniciarHorasMes` para poner a cero. Ambas dejan traza con `_regLog('voluntariado', …)`. La lista de Socios muestra la columna *Horas/mes*.
- **Especies domésticas**: `Dashboard._especiesDomesticas()` (`Perro, Gato, Conejo, Hámster, Pájaro, Tortuga, Hurón, Cobaya, Erizo, Pez`) alimenta el `<select>` de *Nuevo/Editar Animal* y el de *Alta de camada*; `Otro...` (texto libre) sigue disponible en la ficha. El **filtro de especie de *Animales* es dinámico**: lista las especies presentes en el inventario (las conocidas primero) en vez de un `Perro/Gato/Otros` fijo. **NO existe encuesta propia de otras especies**: adopción y acogida de cualquier especie se tramitan con `pre-adopcion-perros`, `pre-adopcion-gatos` y `pre-acogida` (el selector de asignación no filtra por especie). Todo rastro de `otras-especies` (tarjeta del hub, ruta `#encuestas-otras`, entrada en `gen-config`) **está retirado** hasta que exista el formulario.
- **Fechas y horas visibles**: `Dashboard._fmtFecha`/`_fechaCorta` usan el formato estándar `AAAA/MM/DD` y añaden `hh:mm AM/PM` cuando el dato trae hora; también reconocen el texto es-ES antiguo de las hojas. Los PDFs y el carnet reutilizan el mismo formato. Los datos siguen guardándose en ISO: el formato es solo de presentación. Tests en `dashboard.test.js` y `cobertura.test.js`.
- **Analítica en Reportes**: `Dashboard._cardAnalitica()` = análisis de respuestas por survey/estado + duración media de acogidas + horas de voluntariado y top del mes. Las fechas pasan por **`Dashboard._partesFecha(f)`** → `{y, m, d}` o `null`, que entiende ISO (`2025-04-13`), `dd/mm/aaaa`, **`dd-mm-aaaa`** y texto es-ES **`'13 abr 2025'`** (así guardan las acogidas `inicio`/`fin` con `toLocaleDateString('es-ES', {month:'short'})`; ojo, septiembre sale **`sept`**, 4 letras). Sobre eso montan `_tsFecha` (timestamp UTC) y `_anioFecha` (año). Sin esa rama la duración media de acogidas salía siempre vacía y `13-04-2025` se descartaba.
- **Memoria anual**: `_memoriaData(year)` suma `gastos`/`donaciones` por `importe`, pero **los apadrinamientos guardan el aporte en `aporte_mensual`** (`_totalAportes`): `apadrinaTotal` usa `aporte_mensual ?? importe` o la cifra salía 0,00 €.
- **Hub encuestas (móvil)**: bottom nav unificada en `Inicio | Encuestas | Animales | Más`. "Encuestas" abre un hub con 3 tarjetas (perros/gatos/acogida) que redirigen a sus listados; la sidebar de escritorio/tablet conserva los 3 enlaces directos.
- **Navegación por viewport**: móvil (≤767px) usa bottom-nav + sidebar como drawer; tablet (768-1023px) y escritorio (≥1024px) usan sidebar fija (rail colapsable en tablet). Reglas nav separadas por breakpoint; contenido intacto. Desde **v136** la bottom-nav marca como activa la **pestaña padre** (`App._bottomParent(page)`: `encuestas-*` → Encuestas, páginas de gestión → Más, `animales`/`dashboard` directos) con `aria-current`, y el menú **Más** refleja la página activa (`aria-expanded`/`aria-controls`). El menú «Más» es desplazable con altura máxima y **recupera Reportes**; topbar muestra el título de página truncado y respeta `env(safe-area-inset-*)` igual que sidebar, bottom-nav y el padding inferior del contenido, el login y los modales.
- **Táctil por `pointer:coarse`**, no por viewport: botones/inputs/links a 44px en móvil, tablet y portátiles táctiles (el bloque `max-width:767px` solo afina layout).
- **Sidebar por secciones plegables**: los grupos (Encuestas/Gestión/Herramientas) son acordeón (`data-section`, estado persistido en `gn_sidebar_sections`); en rail (`collapsed`) los iconos siempre visibles para no perder acceso.
- **Rutas relativas obligatorias** en el frontend: GitHub Pages sirve bajo `/admin-dashboard/` (rutas absolutas `/css/...` → 404).
- Feedback de estado en `Dashboard.setEstado`: muestra loader y revierte el estado si falla.
- **Multiusuario y caché por cuenta (v127)**: `Auth._syncUserStorage` persiste `gn_data_uid` y limpia datos/caché al cambiar de cuenta sin tocar preferencias de interfaz; `Dashboard.setUser`/`resetUserState` vacía memoria, DOM y modales; `_canPersistUserData` bloquea escrituras de una pestaña que aún tiene la cuenta anterior; `_loadList` solo conserva registros locales con una operación pendiente (no resucita filas borradas por otro usuario) y `Dashboard.refreshData`/`#refresh-btn` fuerza red para trabajo simultáneo. **Riesgo pendiente**: el backend no tiene roles (todos los usuarios verificados son admin) y las ediciones concurrentes siguen siendo last-write-wins.
- **Sync offline**: escrituras que fallan se encolan (`gn_pending_ops`) y se reintentan al volver la red (`flushPendingOps` en init + evento `online`, badge `.pending-sync-badge`); el backend hace **upsert por `id` en `appendToSheet`** para no duplicar. `RATE_LIMIT` se aplica (fail-open, ventana 60s por token).
- **Init perezoso**: `Dashboard.init` carga en paralelo perfil+encuestas+estados+notas; candidaturas/acogidas/contratos van en fondo y cada pantalla/ficha los asegura con `_ensureListas` (best-effort, nunca lanza). Arranque con `gn_session`: si hubo login previo se muestra loading directo, sin flash del login (`Auth._resolved` + timeout 12s).
- **Borrado de adopción con rollback**: `delete-adopcion` usa `deleteAdopcionCascade` (backend) + espejo en `Dashboard.deleteAdopcion` (front): animal→`disponible` (solo si lo reservó ese caso), solicitud `aprobada`→`en_proceso` (vía `solicitud_id`=`survey::resp`), candidatura→`en_lista` sin animal. El caso enlaza su cuestionario con `Dashboard.viewCuestionarioModal` (modal `info-modal`, solo lectura + PDF/salto a Encuestas).
- **Borrado de acogida con rollback espejo** (solo front): `Dashboard.deleteAcogida` + `_rollbackSolicitud` compartido (también lo usa `deleteFamilia` por caso): animal→`disponible`, familia restaura capacidad, solicitud→`en_proceso`, candidatura→`en_lista`. Finalizar pide confirmación (`avanzarFaseAcogida`).
- **Escapeo del cuestionario en el render**: el HTML de las secciones lo construye **`Dashboard._seccionesHtml(sections)`** (pura, testeada), que escapea `s.title`, `f.label` y `f.value` con `_esc`. La usan la ficha (`viewDetail`) y el modal (`viewCuestionarioModal`). **NO escapear en `_buildSections`**: `pdf-export.js` hace `_esc(f.value)` por su cuenta y saldría doble-escapeado. Campos de animal/socio/adopciones/familias también van con `_esc` en su render.
- **`setEstado` devuelve booleano**: `true` si el backend guardó, `false` si falló (revierte el estado optimista y pinta el error con `_snackErr`). Cualquier llamante que pinte «éxito» tras cambiar un estado (`aprobarEncuesta`, `descartar2025`, etc.) **debe comprobar el retorno** y abortar si es `false`.
- **Token de API SOLO en query (nunca cabecera `Authorization`)**: `api.js` envía el JWT **únicamente** como `?token=` en la URL (el backend **desplegado** solo lee `e.parameter.token` y responde `ACAO: *`). **NO añadir cabecera `Authorization`**: un header no simple fuerza un preflight CORS (`OPTIONS`) que Apps Script **no** responde con `Access-Control-Allow-Headers`, y el navegador bloquea **todas** las peticiones (rompió prod con «error al cargar» — v105). Solo migrar el token a cabecera **cuando el `Code.gs` esté desplegado con soporte de preflight**; entonces retirar el query (saca el JWT de logs/red).
- **Iconos PWA desde el logo del login**: `scripts/gen_icons.py` genera los iconos desde `logo-nebak.jpg`. `icon-192.png`/`icon-512.png` son RGBA con **recorte circular** y esquinas transparentes (el blanco del logo forma el círculo, como en el login); `icon-maskable-192.png`/`icon-maskable-512.png` llevan **fondo blanco `#ffffff`** y el logo dentro de la zona segura; `icon-180.png` es el apple-touch-icon opaco con el mismo blanco. `manifest.background_color` debe seguir siendo `#ffffff` para que el splash de Android sea uniforme: tanto el icono `any` (transparente) como el `maskable` (blanco) se funden con el fondo. `logo-nebak.jpg` se mantiene para login/sidebar. Regenerar con `python scripts/gen_icons.py` si cambia el logo.
- **Capacidad de familias**: `_capacidadFamilia(actuales, max)` → `Ocupada` solo cuando `actuales >= max` (falta de max ⇒ 1). Antes se marcaba `Ocupada` con cualquier animal y una familia con `max_capacity=2` se quedaba inútil tras la primera acogida. La usan `_crearCasoDesdeCandidatura`, `avanzarFaseAcogida` y `deleteAcogida` (rollback).
- **Lista negra con clave estable**: las tarjetas pasan `_blClave(bl, idx)` = `id` si existe, si no `idx:<i>` con el **índice de la lista completa** (antes se pasaba el índice ya filtrado por la búsqueda, y un borrado con filtro eliminaba a otra persona). `_blPorClave` resuelve; `saveBlacklistItem` con `idx:` crea registro nuevo (el backend necesita id); `removeBlacklistItem` sin id solo quita de local.
- **Tokens de diseño en CSS**: todo `font-size` ≤ `0.72rem` usa `--text-2xs`/`--text-xs`/`--text-sm`; los hex sueltos se sustituyeron por `var(--success)` (`#16a34a`), `var(--info-strong)` (`#2563eb`), `var(--primary-lighter)`/`var(--info-light)` y `var(--gray-400)`. Al cambiar un token, revisar `tests/diseno.test.js` (lee el CSS).
- **Glassmorphism por capas (v124)**: sistema de superficies, no reglas sueltas. Tokens `--surface*`, `--glass-1/2/3`, `--glass-border*`, `--glass-blur*`; nivel 1 chrome (sidebar/topbar/bottom-nav), nivel 2 contenedores/paneles, nivel 3 modales y menús. El vidrio real solo se activa en `@media (min-width:768px) and (pointer:fine)` con `@supports (backdrop-filter)`. **Datos, tablas, campos, documentos y el contrato son siempre opacos** (sin blur anidado); en móvil/táctil todo cae a superficie sólida por rendimiento (`@media (max-width:767px), (pointer:coarse)`). `body::before` mantiene los orbes. Al tocar tokens o reglas, revisar `tests/diseno.test.js`.
- **PWA instalable (v107)**: manifest completo (`id`, `scope`, `display_override`, iconos `any`+`maskable`, atajos, categorías), `src/js/pwa.js` (botón de instalación Android/escritorio vía `beforeinstallprompt` + guía iOS, detección standalone), `src/offline.html` (fallback offline) y SW con precache ampliado + navegación network-first. Splash con `background_color` `#ffffff` e iconos que se funden con él: `any` transparente y `maskable` blanco (sin cuadrado).
- **`docs/` legado = HISTÓRICO**: `ARQUITECTURA`, `CHANGELOG`, `CHECKLIST-PRODUCCION`, `FLUJO-TRABAJO`, `GUIA-DESPLIEGUE`, `ROLES` y `ESQUEMA-FLUJO-PREADOPCION-ACOGIDA` llevan encabezado que remite a `AGENTS.md`/`PROGRESO.md`. Los docs vivos son `ANALISIS-ETIQUETAS-ENCUESTA-ANIMAL.md` y `GUIA-TOKEN-INSTAGRAM.md`.
